# Offline statistical analysis

The scripts use Python 3.10-compatible syntax (checked with `ast.parse(feature_version=(3,10))`). Install dependencies with a recent pip that selects versions compatible with the chosen interpreter. The validated environment uses Python 3.14, NumPy 2.5.4, SciPy 1.18.1 and Matplotlib 3.11.2. Installed package metadata requires Python ≥3.12 for these NumPy/SciPy versions and ≥3.11 for this Matplotlib version; Python 3.10 therefore needs older compatible releases within the requirements ranges. Runtime validation on Python 3.10 has not been performed.

Run `python -m pip install -r requirements-analysis.txt`, then
`python analysis/analyze.py results/trials --output results/analysis`.
The tool accepts trial JSON files, directories recursively, or JSONL. It skips manifest/progress objects and rejects incomplete, unverified, erroneous, duplicate or unsupported trials. Use an output directory outside the input directory. Outputs include full per-trial and per-case CSV/JSON, charts and a linked Markdown report. Preserve raw trials alongside derived results.

Experiment labels are arbitrary and preserved verbatim (for example `mac-local`, `pi-local`, or `paco-local`). Compare selected labels using `--baseline mac-local --candidate paco-local`; comparison matches only identical file size, block size, concurrency, pattern and operation. Both flags are required together and labels must be present and distinct. If neither flag is given and unique `gen2` and `gen3` labels exist (case-insensitive), those two are compared automatically. Other labels remain in summaries and plots, with no inferred comparison. The gain chart uses the selected candidate/baseline labels. Reports show observed repetition counts for any experiment.

The optional predefined gen2/gen3 campaign comprises 2 modes × 3 file sizes × 4 block sizes × 3 concurrency settings × 5 patterns × 10 repetitions = 3,600 trials, 180 cases per mode. Pass `--check-gen-campaign` to flag incomplete counts against these exact dimensions; generic experiments do not assume this campaign. Inspect the manifest for each experiment's intended dimensions. No absent case is imputed.

For each case and operation, the tool summarizes bandwidth (MiB/s), IOPS, mean latency, P50/P95/P99/P99.9 latency (µs): sample n, min/max, arithmetic mean, median, all exact modes, sample standard deviation (n−1 denominator), CV (standard deviation/mean), P5/P95 across repetitions, and two-sided 95% Student-t confidence intervals for the mean. CI and sample standard deviation are undefined at n=1; CV is undefined at mean zero. Across-repetition P5/P95 use NumPy's default linear interpolation. Exact mode is `none/all unique` if no value repeats. Predefined binned modes use half-open bins anchored at zero, width 10 MiB/s or 1,000 IOPS; all tied intervals are returned. Latency has no binned mode.

Rates divide completed bytes/operations by actual measured seconds, including the last completion. Mixed workloads retain read/write results separately; combined rates sum bytes/operations and combined mean latency is weighted by operation count. Combined quantiles pool read/write histogram counts, never average percentiles. The 1,024 histogram bins have 16 subdivisions per power-of-two nanosecond octave. Quantiles use nearest-rank and the containing bin's inclusive upper bound, converted to µs. They are bounded estimates, not exact individual latencies. Per-case statistics of percentile metrics describe variation of each trial's percentile, not the percentile of all campaign operations. Read/write histograms must each sum to their operation counts.

Confidence intervals treat trial means as independent samples; they do not account for temporal dependence, warmup bias, hardware drift or systematic measurement error. Randomized campaign order mitigates some drift but cannot establish independence. Compare like cases and inspect distributions/variation. Ratios in the gain chart are ratios of mean bandwidth, without ratio confidence intervals. Curves fix every dimension except the horizontal sweep; many curves are overlaid to reveal broad shapes. Scatter points and error bars are case means.

`analysis/validate_synthetic.py` creates explicitly marked synthetic fixtures in a supplied temporary directory and verifies numerical invariants. These are software validation only, never hardware performance evidence. The analyzer refuses them unless `--validation-only` is supplied and titles their report accordingly. No generated benchmark result is committed.

## Reading workload and tail shapes

Paginated `overview_bandwidth_mib_s_*.png` and `overview_p95_latency_us_*.png` fix file size by row and pattern by column, sweep block size on a log axis, color experiment labels, and distinguish worker counts by line style. Mixed cases use the combined operation view; other cases use the active direction. P95 curves show the arithmetic mean of each repetition's P95, rather than a pooled P95. Pages cap file sizes at two, patterns at three, labels at four and worker counts at three to keep legends and panels readable. Generic experiment labels and workload sizes are retained.

`pooled_ccdf_*.png` fixes file size, pattern, block size and worker count in each panel. Its curves pool the actual histogram counts across repetitions and active read/write directions for each label. Every operation receives equal weight, so longer or faster trials contribute more observations. This answers a different question from the variation across trial percentiles. The complementary cumulative distribution shows the fraction at or above each occupied bin's lower boundary; only histogram resolution is available. Steps between boundaries are a quantized visualization, not reconstructed raw samples. A zero lower boundary is placed at 0.0005 µs for the log axis. At most nine panels and six labels appear per page. `pooled_histograms.csv` and `.json` preserve the exact integer pooled counts, sample counts, repetition counts and operation selection for audit or further plotting. No histogram is averaged or fabricated.

Every exported chart from `--validation-only` visibly carries a `SYNTHETIC VALIDATION ONLY` watermark; synthetic input remains rejected without that flag. Ordinary real-data exports have no synthetic watermark.

When the engine supplies exact `latency_ns.min` and `.max`, per-trial outputs also include `min_latency_us` and `max_latency_us`. Mixed combined extrema take the minimum and maximum across active directions. Older trials without these fields omit these metrics rather than infer extrema from histogram bounds. Their per-case summaries describe the distribution of **trial extrema**: for example, `min` of `min_latency_us` is the smallest observed individual I/O latency, while `mean` of `min_latency_us` is the mean of trial minima. These differ from the min/max across trial mean latencies and from quantized histogram percentile estimates. The per-case `n` shows how many trials supplied each optional metric.

Mixed combined bandwidth sums read and write traffic. On a full-duplex link, this bidirectional total can exceed a unidirectional bus payload ceiling even when each direction remains within that ceiling. Compare like patterns and operation directions; do not infer link overclocking or a higher negotiated link rate from the sum. Directional read/write statistics remain separate in the exported datasets.

## Portable system checkout reports

`python analysis/analyze_checkout.py checkout.json --output system-analysis --source-commit COMMIT` analyzes a completed `knurl-check check` JSON offline; it runs no workloads. It preserves C-engine statistics and their recorded percentile/CI methods, exports all repetitions and individual RTTs as CSV/JSON, copies the exact input with SHA-256 provenance, and generates CPU, memory working-set and network request-size figures plus a linked Markdown report. No earlier development runs are combined. Disk results remain separately linked. System checkout inputs marked synthetic are rejected, including with `--validation-only`; that flag only marks presentation exports. Duplicate modules, incomplete/unverified runs and nonfinite measurement/statistic fields are also rejected. Reports describe only modules present. `python analysis/validate_checkout.py checkout.json --analysis-dir system-analysis` validates these guards and exact dataset preservation offline, using small derived negative fixtures and a genuine CPU-only subset.

Loopback results are visibly labelled as software-path measurements, not physical network performance. Memory allocation and scratch-file verification cover only the requested working sets/files; they do not verify all installed RAM/disk or assess SMART health. Short application kernels and pointer-chase timings are not peak-performance or hardware-certification claims.
